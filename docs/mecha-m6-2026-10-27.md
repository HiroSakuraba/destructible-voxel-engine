# M6 — third-person mecha controls, jump jets, lock-on and procedural leg segments

## Scope and architecture

This feature builds on merged M1–M5, preserving the existing top-down/tactical mecha contract for older scenes and adding an opt-in third-person presentation. The generated **Iron Yard** selects third-person by default through the validated `dve.prototype.mech_player.camera_mode` component property.

M6 deliberately reuses `GameWorld` polygon/voxel sweeps and raycasts. It does **not** introduce a new physics backend or switch existing prototype genres to a different up axis.

### Controls

- **WASD** — camera-relative XY movement in third person (world XY in tactical mode); independent chassis yaw.
- **Mouse / right stick** — third-person camera orbit (horizontal yaw, clamped pitch). The upper turret follows camera heading when no target is locked.
- **C / gamepad East** — switch between third-person shoulder camera and tactical top-down view. Existing scenes default to tactical.
- **Space / gamepad West (hold)** — jump jets; power-limited Z-axis thrust, persistent vertical velocity, gravity and collision-tested landing.
- **Tab / gamepad North** — lock, cycle through visible living targets by stable key, then unlock. The torso tracks the selected target, including when the player moves. Cover blocks initial target acquisition and can break lock.
- **Shift** — horizontal boost; uses existing energy system and shares its resource pool with jump jets.
- **Mouse 1 / 2** — existing autocannon / rocket attacks. These continue to use authoritative world collision.

### Camera

The third-person camera is positioned over the shoulder, at an 11-metre boom distance, with orbit pitch limited to protect the world-up projection. A projected green target bracket uses the active camera basis when lock-on is engaged. Before accepting the desired boom, a GameWorld ray checks for intervening polygons/voxels; the boom retracts when close to cover. Camera interpolation retains the existing smoothing strategy.

Tactical camera remains available at any time without restarting, and the HUD shows the active mode.

### Jet controls and physical limits

The configuration adds validated `jet_acceleration`, `jet_drain` and `jet_height` fields. A held jumpjet accelerates upward against gravity, with capped vertical speed and a hard maximum jet apex above the player's initial spawn. When the jet stops, gravity continues; the same swept capsule used for lateral movement handles roofs, walls and floors. Jumping is opt-in, so existing M1–M5 planar-only test scenes remain unchanged.

The engine intentionally does not teleport the player to the ground when airborne. Landing is determined by physical swept collision. If an authored level contains no floor, the mech can fall; the M6 tests include physical floor geometry.

### Procedural mecha legs

Iron Yard now renders a separate waist with four independent, visual-only, kinematically animated segments: left/right thigh and shin. The `dve.prototype.mech_leg` role validates one segment per combination of side (`-1`, `+1`) and part (`0` upper, `1` lower); scenes may omit legs for compatibility. Stride phase advances with horizontal distance, opposing legs animate out of phase, and airborne segments hold a neutral pose. Leg transforms follow chassis yaw and position but do not create colliders.

This is **procedural rigid-segment gait**, not a full skeletal IK rig: no planted-foot inverse kinematics, terrain-conforming ankles or animation retargeting yet. Those need a later authoring/rig integration tranche.

### Target lock

The lock selector scans alive and enabled authored targets, restricts range to 85 metres, applies forward-biased acquisition and uses the world raycast to exclude cover-obstructed enemies. Stable actor keys make selection deterministic and saveable; invalid or destroyed locks clear during gameplay.

The torso rotates toward locked targets, but the projectiles still use the existing M2–M4 hit, damage and LOS rules. Missile steering/guidance is not part of M6.

### Saving

`game.mecha.v1` is the stable application-section **name**, not the controller payload schema. The controller payload increments from `DVE_MECHA 1` to `DVE_MECHA 2`, appending the M6 camera mode, yaw/pitch, airborne flag, procedural gait phase and selected target key. The decoder still accepts the earlier v1 format (with default M6 state). No engine-wide DVESAVE file version increment is required.

### Verification

`dve_mecha_m6_tests` exercises both cameras, camera retraction against polygon cover, jumpjet ascent/energy/landing, deterministic target-lock cycling and death release, opposing leg motion, malformed state rejection and both v2 and legacy v1 state restore, camera-relative travel, roof collision, and on-screen lock-bracket projection. The existing M5 save regression now expects the v2 controller envelope.

Build and run:

```sh
cmake --build build --target dve_mecha_m6_tests dve_mecha_m5_tests dve_create_mecha dve_player
ctest --test-dir build -R "dve_mecha_(m6|m5|m3_m4|game)_tests" --output-on-failure
```

### Explicit limitations

Third-person camera interpolation and leg motion run in the fixed simulation step; high-quality render interpolation and a full skeletal rig remain to be developed. Lock-on is yaw-only because the M2 hitscan and rockets remain horizontal. The jumpjet has authored thrust-height limits but is not a six-degrees-of-freedom flight model.
